本轮针对既有 `~/Library/Application Support/InkwiseK12/workspace`，在完整备份和副本演练后完成兼容升级。应用以默认目录、默认端口 8766 启动；新评分、教师复核操作与实际报告下载均已通过。

## 差异与处理

- 旧库仅缺少 `revision_assessments`，已有九张表的列、类型和约束与当前版本一致，无未知表。
- 原 `running.json` 指向已不存在的进程，端口和工作区文件均无活动占用；标记随整目录备份保留，再按启动器的陈旧状态处理流程退役。
- 原默认配置使用云端评分。本轮保留原配置备份，将新任务切到现有本机 `inkwise-deepseek-local`，关闭云端并将费用上限置零；主评分凭据清空，避免把旧云端凭据发送给本机服务。没有发起云端新评分。
- `doctor` 原来将缺少附加表也称为“缺少基础结构”，容易误导为重建数据库。现在明确提示停止工作区、备份并运行 `upgrade-check`；检查仍不自动初始化。

## 备份、演练和迁移

1. 离线备份整个工作区：29 个文件、473,280 字节。目录权限 0700，备份文件权限 0600；原件、副本逐文件 SHA-256 一致。
2. 对备份数据库执行完整性和外键检查，均通过；再恢复一个独立副本，核对全部原有表数据摘要。
3. 在独立工作副本上使用当前 `inspect_upgrade` 和 `initialize_database` 演练：只增加缺失空表，原九张表、41 条记录逐表摘要一致。
4. 正式库执行现有 `init-db --backup-file`，由原备份的精确摘要通过门禁后补表。未重建表、未转换原正文、未改写成绩或重新生成旧报告。
5. 正式库完整性、外键和停止状态兼容检查通过；27 个非数据库/运行标记文件在迁移时保持原摘要。旧凭据、规则、原稿和备份资产保留。

完整备份、逐表摘要及操作回执留在本机私有验收目录，不进入 Git。只读的 `upgrade-check` 不承担备份创建或旧状态清理；无法确认进程归属、存在活动 WAL/journal 或出现未知结构时仍须停止升级。
