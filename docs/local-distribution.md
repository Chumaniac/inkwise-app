# 本机可用版 0.7.0

此版本通过私有 GitHub Release 交付。仓库、安装包和访问文件不转为公开；模型、作文、报告、账号文件及数据库不进入安装包。

## 安装和启动

1. 使用已授权的 GitHub 账号下载 `v0.7.0` 对应 Mac 安装包和 `checksums.txt`，先执行 `shasum -a 256 -c checksums.txt`。
2. 解压到自己的应用目录，保留原目录结构。需要 Python 3.12 和 uv；启动器使用锁定的 `uv.lock` 安装运行依赖，不要求 Git 或前端编译器。
3. 双击 `Start Inkwise.command`。首次创建独立私有工作区，随后打开 `http://127.0.0.1:8766/workspace/`。
4. 从启动器提示的 `teacher-access.txt` 本地文件取得访问值并登录。不要把访问值复制到聊天、截图、Git 或公开记录中。

默认工作区在 macOS 的 `~/Library/Application Support/InkwiseK12/workspace`，配置和教师/教研/管理员访问文件为0600，目录为0700。已有工作区不会被重新初始化或覆盖；升级时保留数据目录。需要独立验收环境时，启动器接受 `--data-dir /新目录 --port 其他端口 --no-open`。

Mac 包含本机 Vision OCR。已有 `inkwise-deepseek-local` 和 `bge-m3` 模型缓存直接复用；若本机模型服务未启动，启动器可启动已安装的 Ollama，仅绑定回环地址，不下载模型、不启用云接口。未准备模型时明确停止并给出就绪检查，不返回伪造分数。初始量规是13套练习草案，未获学校批准；模型报告必须由教师复核。

## 完整使用流程

登录 → 新建批改 → 输入文本或上传图片 → 核对并确认原文 → 选择量规并排队 → 等待本机模型 → 核对原文引用和各维度建议 → 教师修改与确认 → 下载绑定当前版本的报告。知识库复用仍需另外脱敏并取得授权。

关闭前用 `Ctrl+C`，或运行 `Start Inkwise.command --stop`。这会停止本应用及其自己创建的模型进程，保留数据库、图片和成功报告。已经由其他进程启动的模型服务不会被关闭。再次启动后继续使用原工作区。

## 发布与验证边界

`scripts/package_local_release.py` 只从明确 Git 提交的源码白名单构建 ZIP，固定条目时间并记录文件摘要；拒绝链接、路径穿越、私有数据目录和覆盖现有安装包。Mac Vision 可执行文件必须显式提供。包内包含源码、锁定依赖、前端、候选教学资料与启动器，实际私有工作区在首次启动时另建。

安装后的启动器先核对分发文件摘要；服务只监听本机。此交付是本机使用版，不是公网学校部署、学校量规认证或真实学生一致性验收。长文 Kafka、外部知识服务和云模型依然需要明确配置与对应授权。


### 当前任务入口

任务详情按当前状态显示原文核对、评分复核、校对复核或已确认报告入口。按钮只滚动并定位到对应区域，保留未保存的编辑，不提交原文、不批准报告，也不重试处理。未完成任务先查看失败说明；结果未知的请求仍需管理员核查。退出与新建任务会清除旧任务提示。

## 当前源码候选：升级前先核对

当前 main 的能力不能由旧 `v0.7.0` 下载包代替。候选 `distribution.json` 逐项绑定唯一源码提交、文件摘要及 `baseline/v1`、`writing-revisions/v1`、`revision-reassessment/v1`；本轮没有覆盖旧 Release。

对选定的本机工作区，先停止应用与 Worker，再运行 `Start Inkwise.command --data-dir /选定工作区 --upgrade-check --no-open`，或 `inkwise --env-file /选定配置 upgrade-check`。检查只读，不启动模型、API，不复制数据，不初始化数据库。输出只有表/能力名称、容量和固定原因码，不含作文、账号或配置值。兼容返回0，待初始化/升级返回2，无法安全核对返回3。

1. `upgrade_required` 表示仅缺少已知附加表。先在受保护位置保存整个工作区的离线备份；数据库备份必须是应用停止、没有活跃 WAL/journal 时的逐字节副本，文件权限0600，不能是链接或数据库本身。
2. 用 `upgrade-check --backup-file /私有数据库副本` 核对内容摘要。检查预留两份数据库大小加64MiB空间，单库最多2GiB；更大数据库、未知表、字段/约束变化、非本机 SQLite 或在运行工作区需另行安排升级。
3. 先对独立的合成/获准副本执行 `init-db --backup-file /私有数据库副本`，再重复 `upgrade-check` 并重开旧记录。现有本机库缺附加表时，`init-db` 也要求这份已核对备份；启动器不自动迁移。只有已知附加表被追加，原始记录和备份不替换。

若只有旧 `running.json`，先核对进程开始时间、启动命令、端口及数据库文件占用，保留标记备份后才能退役；不能只凭 PID 不匹配或检查报错就删除。升级前也要核对所选配置的模型位置与费用，数据库兼容不代表模型路由已改为本机。已有默认工作区的安全升级与报告保全实例见[正式验收记录](default-workspace-acceptance.md)。
4. 正式切换前按自己的数据授权重复检查。数据库副本校验不证明图片、报告或整工作区备份完整；这些仍需一并保留并独立核对。本轮没有操作当前用户数据库。

降级核对可显式传 `--target-data-feature baseline/v1`（需要修订能力时再追加 `--target-data-feature writing-revisions/v1`）。目标不认识的修订或复评表已有记录时返回 `downgrade_data_present`，禁止用新启动器继续该切换。旧版启动器本身并不认识此新检查，不能宣称它会自动阻止降级；保留旧安装，只给它单独的旧数据副本，不用它处理新库的内容清除。没有新能力记录时也须在副本验证旧版后再回新版。

这是一份停止工作区时的观察，不是锁定未来写入的许可；检查后工作区若被启动或改变，需停止并重新检查。新工作区仍由既有初始化流程建立。健康候选启动会先核对完整数据兼容性，再进入原模型/量规就绪检查；不伪造评分，不下载模型。
